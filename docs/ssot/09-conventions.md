Status: Draft | Last updated: 2026-11-26

## Verified layout

- Root: package.json/package-lock.json, tsconfig.json, next.config.ts, eslint.config.mjs, .gitignore and AGENTS.md.
- `node_modules/`, `.next/` and ignored .env.local exist locally; generated/dependency files are not source.
- No database code, schema or migrations existed at initial audit.
- Phase 1 adds `src/db/index.ts`, `src/db/schema/index.ts`, `src/app/api/health/db/route.ts`, root drizzle.config.ts and `docs/ssot/`.
- `drizzle/` is the configured migration output directory; no business migration is required for an empty schema.

## Implementation rules
- Use strict TypeScript (already enabled); `@/*` resolves to `./src/*`.
- Preserve Next.js special filenames (page.tsx, layout.tsx, route.ts). Other file naming remains undecided.
- Server Components are the default; use client boundaries only where interactivity requires them. Database and provider secrets remain in server modules. Do not pass secrets through serialized props.
- Product styling uses SCSS, no Tailwind. Phase 2 replaces starter CSS with src/app/globals.scss for the minimal login/application shell and uses a system font without build-time font downloads. Broader styling organization remains open.
- API failures use generic responses; retain useful sanitized diagnostics only in server logs.
- Read relevant installed Next.js guides before writing framework code and heed deprecations.
- Update SSOT in the same commit whenever decisions change.

## Approved Phase 3A data conventions (2026-11-24)
src/lib/data/ holds server-only company/contact/lead CRUD and common safe errors. Under the approved Phase 3A revision, functions take plain inputs and never perform auth themselves. Future actions call the existing auth helper first; future webhooks verify provider signatures/tokens first. No AuthenticatedContext/getDataContext interface remains. Shared pure modules: lead-values.ts, normalize.ts, contact-merge.ts and validation.ts. tests/*.test.mjs use Node's test runner and direct TypeScript imports; npm test accesses no environment file or database.

Lists accept optional literal substring search, page (1 through 1,000,000), pageSize (1 through 100, default 25). Lead lists filter status/source/contact; contact lists filter company. Companies search name; contact and lead searches use contact name/phone/email, including stored normalized identifiers. Wildcards in search text are escaped. Order is created_at descending, then UUID descending. Offset pagination and count/items are separate queries: concurrent writes may change totals between them. Lead DTOs return budgetPaise as decimal strings; database operations retain bigint. Other DTO timestamp values are Date objects, serialized by the framework/JSON boundary.

Known data-layer conflict behavior: conflicting phone/email owners require manual resolution; existing-contact merges are not implemented. Soft deletion never cascades, and parent visibility does not silently hide live child entities. Relationship changes validate/lock a live parent. No restore API, hard-delete API, assignment fields, activity creation or business UI/routes are introduced.

Phase 3A migration work is manual: generate/review schema SQL, then append drizzle/drafts/phase-3a-triggers.sql to the generated migration before application. Check .enableRLS() output and source/status/lost/contact-method checks plus partial uniqueness/FK/index definitions. Draft supplements are never automatically executed. The old Phase 2 draft is superseded; 0002 is the forward repair for the empty recorded 0001.

## Phase 3B UI layout (2026-11-24)
Phase 5 additions (2026-11-25): /activities, /activities/new and /activities/[id] use private _crm/activity-* modules, existing shared RecordForm/DeleteForm and crm.scss. RecordForm supports controlled target selects and datetime-local fields. New target options are active contact/lead/deal records; changing target type clears the old selection. Details retain an unavailable existing target option so unrelated edits/completion can continue without resurrecting a parent. RelatedActivities is a server component that authenticates first, checks schema readiness and queries only the primary linked record. Quick actions and all mutations authenticate before calling plain-input data functions, validate shared schemas, sanitize errors and revalidate affected paths. No globally cached user data.

Activity time logic is isolated in src/lib/activity-time.ts and tested without relying on the machine/browser timezone. Forms convert India local minute values to absolute instants before shared schema validation; backend due_at/completed_at use Date objects mapped by Drizzle. Completion timestamps never come from form input. src/lib/activity-values.ts drives SQL CHECK values, Zod and labels. scripts/verify-activity-foundation.mjs reads sanitized metadata through both DB connections; scripts/check-activity-constraints.mjs uses synthetic rollback-only fixtures and never edits existing rows or prints IDs/raw errors. Migration 0006 includes the reviewed trigger supplement; no activity seeds or notification jobs are needed.

Phase 4 additions (2026-11-25): /pipeline, /deals, /deals/[id] and /leads/[id]/convert use private _crm/deal-pages.tsx, deal-fields.ts and deal-actions.ts. Stage movement uses a labeled select and submit form; no drag/drop dependency. Outcome is separate from stage. Server actions authenticate before calling session-independent data functions, validate strict shared schemas, and revalidate affected deal/pipeline/lead paths. The new data/deals.ts exports a catalog/seed readiness gate so pending setup cannot break the existing lead detail query. SQL supplements remain in drizzle/drafts/ and are manually appended to generated migrations. scripts/verify-deal-foundation.mjs is read-only and checks both runtime and migration connections without printing connection values or business records. Pipeline/deal state uses standard SCSS, system fonts and Suspense; no global user-data cache.

`src/app/(protected)/companies/`, `contacts/` and `leads/` each have list, new and [id] routes. Private `_crm/` modules contain shared forms, navigation, pagination, server page components, read helpers and server actions; `crm.scss` provides responsive tables/forms/navigation using the existing system font. Protected loading and not-found files provide route feedback. List/detail/new page reads independently await requireUser() inside Suspense boundaries; no user data is globally cached. Every exported mutation action calls requireUser() before any data function, validates shared Zod input, sanitizes errors and revalidates affected list/detail/new paths. Delete actions require an explicit confirmation checkbox and only soft-delete.

Lead actions force entry_method=manual. New enquiry forms delegate contact reuse and lead insertion to createLeadWithContact; success links the reused contact and conflicts surface without merging existing contacts. Inline company creation is a separate explicit save before enquiry submission: it remains saved if the enquiry is abandoned or fails. Company selectors currently load all active companies; an unavailable existing company link is retained unless changed. Related leads remain available when their contact is soft-deleted, per data-layer conventions.

`src/lib/money.ts` parses ungrouped non-negative rupee strings into bigint paise (at most two decimal places, signed PostgreSQL bigint upper bound), formats Indian grouping via Intl on bigint, and round-trips editable values without Number conversion. Blank budget is null. Monetary number inputs are rejected. `tests/money.test.mjs` adds pure conversion/formatting tests. Existing legacy negative budgets can display but must be changed or cleared to save through this UI. General count/page arithmetic remains numeric and is unrelated to money.

## Phase 6 commercial layout (2026-11-26)
/quotations, /orders, /payments and /expenses provide authenticated lists/details; new routes exist for quotations/payments/expenses only. _crm/finance-pages.tsx renders server data behind Suspense and checks setup before querying new tables. _crm/finance-actions.ts authenticates first, validates shared Zod inputs, converts rupee fields exactly and revalidates related paths. _crm/finance-forms.tsx supplies draft item editing and explicit status/conversion/void controls; totals shown in the client are previews only. src/lib/data/finance.ts accepts plain input from trusted callers, recalculates authoritative totals, protects document conversion and locks orders for receipt changes. No caller totals, status-at-creation, tax/discount or void timestamps are accepted as financial inputs.

commerce.ts owns six RLS-enabled tables and reference sequences. finance-values.ts and finance-validation.ts are pure/testable; SQL value sets come from shared constants. Migration 0007 includes reviewed draft guard SQL plus timestamp triggers, snapshot completeness constraints and balance/immutability enforcement. verify-finance-foundation.mjs is read-only across both connections; check-finance-constraints.mjs writes only synthetic rollback fixtures with explicit isolated reference numbers and no persisted business data. Script output omits raw errors, IDs and connection values. No printed/PDF documents or outbound delivery is provided; Sent is a manually recorded lifecycle status. Amount correction is void-and-record-again, not an update. No global user-data cache or financial role model was introduced.

## Phase 7 analytics layout (2026-11-26)
/analytics uses _crm/analytics-page.tsx behind Suspense, authenticated before reading search parameters/time or calling plain-input getAnalytics. Date controls are GET forms with validated paired calendar dates, inclusive India boundaries and a bounded custom span; invalid ranges show an accessible error without a DB query. analytics-charts.tsx is a client leaf with animations disabled, bounded relative coordinates and exact INR/count tooltips. Exact semantic tables accompany both charts; empty states are explicit. crm.scss supplies responsive metric grids; nav and dashboard link to analytics. Selected-period deal/lead breakdowns describe current cohort state, not historical movement. All-time snapshots are visibly outside the date filter. Tests exercise pure date/rate/chart helpers; verifiers share the production parameterized SQL. No business data is globally cached or exposed to unauthenticated callers.

## Phase 8 integration modules (2026-11-26)
/api/webhooks/meta-ads, /instagram and /whatsapp delegate to server-only integrations/webhook.ts and pure webhook-handler.ts. webhook-security.ts bounds exact raw bytes and authenticates HMAC before parsing; integration-values.ts validates normalized events; integration-enquiry.ts maps only explicit supported fields. integrations/config.ts exposes presence only and rejects incomplete channel setup. integrations/graph.ts confines provider fetches to fixed origins. data/integrations.ts accepts plain inputs; trust is established by the webhook handler or authenticated retry action first. createEnquiryInTransaction is an internal server-only transaction seam, while createLeadWithContact retains its public plain-input transactional behavior. No existing caller signatures changed.

/integrations renders event metadata/text/state and lead links behind Suspense, calls requireUser before data reads and provides an accessible useActionState retry control. Safe processing codes are stored instead of driver/provider response text; no raw payload, arbitrary custom answers, attachments or credentials are persisted. Event/identity uniqueness is unconditional to preserve replay guards. Pure tests exercise real HTTP handler logic with injected offline dependencies; DB scripts use sanitized metadata or synthetic rollback-only fixtures. check-webhook-http.mjs uses synthetic channel configuration, a temporary local production server and status-only messages, with no business writes; it must not be confused with live Meta end-to-end verification.
